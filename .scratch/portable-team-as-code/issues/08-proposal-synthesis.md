## Question

replaced per binding, amended, or kept separate, and how current work changes
that assessment?

Deliver [the proposal](../proposal.md), using a fresh upstream snapshot, semantic
interfaces, illustrative configuration, accepted demo bounds and a module-level
reuse map. Distinguish agreed direction from recommended implementation shape.
No implementation, remote issue publication or service activation is authorized.

## Review checkpoints and execution prerequisites

- Identify Will's concrete in-flight cache/coordination interface and map it to
  the proposal before freezing extraction scope; follow the upstream watch.
- Review the proposed operation envelope, multi-store consistency and legacy
  compatibility seams against that implementation. Proposed names are not an
  existing command interface or an accepted upstream ADR.
- Before any future demo launch, record exact OS/harness/model versions, numeric
  spend cap, isolated execution environment and launch authorization. The
  approved design defines the bounds but supplies no live budget or activation.

These are explicit review/launch gates, not silently assumed implementation work.
